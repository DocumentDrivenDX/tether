# Tether 0.3.1

A patch release for consuming applications. The API is unchanged from 0.3.0.

## Changed

- **Runtime dependencies are ranges, not exact pins.** The base install now requires
  `pydantic>=2.12,<2.15`, `pydantic-ai-slim>=2.59.0,<2.63` and `anyio>=4.15.1,<5`; the
  `postgres` and `embedded-postgres` extras require `psycopg[binary,pool]>=3.3.6,<3.4`. Each
  range's lowest and highest versions passed the complete suite; see the
  [dependency matrix](../helix/03-test/evidence/dependency-matrix-20261106.md). `uv.lock`
  keeps the exact qualified versions. The `openai`, `tiktoken` and `textual` pins stay
  exact and stay in their extras.
- `pydantic` 2.11 is outside the range: `pydantic-ai-slim` 2.59.0 itself requires
  `pydantic>=2.12`.
- `pydantic-ai-slim` 2.63.0 and later are excluded. Those versions append built-in
  instruction text to the system prompt, which Tether's derived-history check refuses
  (`derived_history_changed`) because unapproved instructions would reach the model.

## Fixed

- The reference Bash tool now waits, for at most 5 seconds, until its killed process group
  has exited before it reports cancellation or completion. On Linux an orphaned descendant
  could still be running for a moment after the shell exited; found by the first Linux
  run of the complete suite. If the group does not exit, the tool raises
  `process_group_exit_unconfirmed` instead of assuming it did.

- The reference terminal UI no longer discards text typed while a new session is opening.
  It cleared the message field after selecting the new session, so a draft entered in that
  window was lost; on a slow Linux runner this made a TUI test wait forever.

## Added

- Wire tests for on-behalf-of calls through the Databricks AI Gateway header profile:
  caller token as the only `Authorization`, five concurrent callers, gateway tags,
  `traceparent`, `x-request-id` on the receipt and error, and `http <status>` errors
  without body text.
- README recipe for an application that holds a per-request user token.
- Embedding guide sections on production limits and on calling Tether from synchronous code.
- A manually dispatched `Release gate` workflow that runs the complete `make check` on
  Linux x86_64 and arm64 with Python 3.11 and can install a published version from PyPI
  into fresh environments. Publication remains local.
- A 0.2.0 publication receipt with artifact hashes and fresh public-index installs on
  macOS arm64, Linux aarch64 and Linux x86_64.

## Defaults

No default changed. `MODEL_EXECUTION_DEFAULTS_VERSION` and `CLIENT_DEFAULTS_VERSION` remain 1.
The `ModelExecutionLimits` defaults are documented as conservative floors that a production
application is expected to override.
