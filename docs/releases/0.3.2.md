# Tether 0.3.2

A patch release for consuming applications that call models through a Databricks AI Gateway.
The API is unchanged from 0.3.1 except for one new optional, defaulted setting.

## Added

- **`databricks-ai-gateway-stream-v1` stream profile**, selected explicitly. Pass
  `stream_profile="databricks-ai-gateway-stream-v1"` to `OpenAICompatModel` or set it on
  `CompatibleModelSettings`; the reference launcher's `--databricks-profile` selects it. The
  profile checks each gateway-specific streaming field against a closed allow-list and removes
  it: the prompt-filter preamble, choice filter results and filter errors, null `logprobs` and
  `refusal`, `obfuscation`, `latency_checkpoint`, `routing`, and reasoning-summary content
  parts. Only the normalized frames reach the strict chunk validator and the SDK. Unknown
  fields still refuse under both profiles. Decision: ADR-013 ("Gateway stream dialect");
  contract: CONTRACT-001 ("Stream profile").
- Reasoning-summary parts are validated and dropped. They never become text, deltas or
  usage.
- Filter metadata is shape-checked and not kept. A prompt category with `filtered: true`
  refuses as `prompt_filtered`; an output category with `filtered: true` must end in a
  `content_filter` terminal.

## Fixed

- Stream-validation failures now carry the observed `x-request-id` and receipt, as the
  CONTRACT-001 outage rule requires.

## Defaults

No default changed. The stream profile defaults to the strict `openai-chat-text-tools-v1`, and
that profile still forwards the original bytes unchanged. `MODEL_EXECUTION_DEFAULTS_VERSION`
and `CLIENT_DEFAULTS_VERSION` remain 1.

## Live evidence

With the new profile selected, the quick, balanced and deep tiers of a development workspace
each passed the on-behalf-of checks P1, P2 (five concurrent), P3 and P5, and the P4 error path
passed: 19 physical calls, 0 application-credential reads. Under 0.3.1 only the balanced tier
completed. See the redacted
[live receipt](../helix/03-test/evidence/databricks-gateway-stream-dialect-20261108.md).

## Not covered

- Nonstreaming gateway responses still use the strict body validator and are not qualified.
- Cache counts the gateway reports under `cache_read_input_tokens` and
  `cache_creation_input_tokens` are not mapped.
