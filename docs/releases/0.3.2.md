# Tether 0.3.2 (unreleased)

A patch release. The API is unchanged from 0.3.1.

## Fixed

- A streamed model reply that Tether refuses now keeps the gateway's request id. When the
  provider answered 200 with an `x-request-id` but the stream failed validation or ended
  early, `ModelUnavailable.request_id` and `ModelUnavailable.receipt` were `None`, so the
  failed call could not be joined to the gateway's logs. Found by the first live run of the
  Databricks AI Gateway caller-identity check; the HTTP-error path was already correct.
  Regression tests in `tests/test_databricks_caller_identity_wire.py`.

## Defaults

No default changed. `MODEL_EXECUTION_DEFAULTS_VERSION` and `CLIENT_DEFAULTS_VERSION` remain 1.
